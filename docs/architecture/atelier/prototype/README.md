## 原型在哪

源码在 `packages/prototypes/desktop/applets/atelier/`（统一原型工作区；独立 web 工程）。本目录只放入口说明，不复制源码（架构文档标准 §5.8）。

这个原型只为**展示 Atelier 终态产品长什么样**，用 React + LobeUI 写成网页给人确认形态；**不碰 Lynx / applet 容器 / SDK**。official applet product unit 已落在 `apps/applets/atelier/`，按 Lynx 运行时与 Station-bundled service binding 继续实现。

> **Atelier 本质是 applet，跑在 peers-touch Desktop 容器里**，不是独立全屏 app。容器外壳（全局 SideNav + 内容区 + applet pins）由 [desktop 容器外壳原型](../../desktop/prototype/README.md) 展示；本原型作为 workspace 包 `@peers-touch/prototype-desktop-atelier` 被 desktop 原型作为一个 applet 嵌入其内容区。本原型也可单独跑起来看 Atelier 自身界面（壳子高度自适应，`height: 100%`）。

## 怎么跑

```bash
cd packages/prototypes/desktop/applets/atelier
pnpm install        # 首次，monorepo 根装也可
pnpm dev            # Vite，浏览器打开 localhost
```

技术栈：React + Vite + `@lobehub/ui`(LobeUI) 优先 → antd 兜底 + `react-layout-kit` + `lucide-react` + `@peers-touch/applet-sdk` + CSS。当前入口已具备 **environment runtime bootstrap**：运行在 Lynx / Web Host applet 容器内时，UI 使用 applet-sdk bridge 调 `atelier.*` 真接口；普通浏览器 / Vite 独立预览时自动回退 mock runtime，不依赖 Station。Host 模式不应把 mock seed 当作真实首屏数据；真实 snapshot 返回前只能展示空壳 / loading / error 状态。

## 形态定调：对话优先（SOLO 式），不是团队项目管理

Atelier 是**个人** Agent 工作台，形态对标 TRAE Work / SOLO 的**对话优先**界面，刻意保持简单：左侧任务列表、中间一条对话流、底部一个大输入框；复杂任务时右侧才浮出 Todo 面板。

**不做**传统项目管理那套（项目树 + 看板 + DAG 计划图 + 多 Agent 协作侧栏）——那是给团队的，对个人太重。

Atelier 的灵魂（多 Agent 协商）不另开团队协作面板，而是**内联进对话流**：平时折叠成一行「🤝 N 个 Agent 协商了 X，已收敛」，点开看角色 / 带证据的反对 / 共识；只有需要你拍板时，决策卡才在对话流里冒出来。

## 任务管理是可插拔 plugin

「怎么组织我的任务」做成**可插拔 plugin**：同一份任务数据，换不同的 plugin 就换一种组织 / 展示方式（项目文件夹分组、简单平铺、Kanban、DAG……）。左栏顶部「管理方式」切换器选 plugin。

- **数据归壳子管，plugin 只渲染 + 委派**：壳子（Page）持有任务与生命周期；plugin 通过 `TaskHost`（`select / setStatus / purge / newTask`）回调改状态，不自己存数据。新增看板 / DAG 只需实现 `TaskPlugin.render`，对话流与数据模型不动。
- **默认 plugin = 项目文件夹分组（对齐 SOLO）**：任务按所属项目 / 仓库文件夹（`Task.project`）分组，每组可折叠、各带「+」新建，对齐 SOLO 的 "Your Task List"。简单平铺降为可选 plugin。
- **完整生命周期**：`active → archived → deleted`。进行中可归档 / 删除；归档可恢复 / 删除；删除进回收站可还原或彻底删除（`purge`）。归档段、回收站段作为分组下方可折叠段。
- 看板 / DAG 在切换器里作为「计划中」占位项，证明形态可换、未实现。

接口定义见 `src/types.ts` 的 `TaskHost` / `TaskPlugin`；plugin 实现见 `src/plugins.tsx`。

## SOLO 外壳对齐（Browser prototype，UNSYNCED with official single-column product shape）

以 SOLO 为外壳人体工学的基准线，在其上叠 Atelier 独有的协商 / 决策 / 预算灵魂。注意：下面的 left rail / right preview panel 是 browser prototype 的交互探索，`UNSYNCED with official single-column product shape`；official Lynx applet 当前使用 controlled single-column projection sections，不以 browser rails 作为运行时产品形态。

- **左栏**：顶部 Work / Code / Design 模式 toggle（视觉态）+ New task / Skills / Automation 入口 + "Your Task List"（筛选图标 + plugin 切换器）+ 项目文件夹分组；标题行可一键收起侧栏。
- **顶栏**：（侧栏收起时显展开按钮）任务标题 + 项目 chip + git 分支（`Task.branch`）+ 打开文件夹 / 终端 / 大纲图标 + Open in IDE + 预算条。
- **对话流**：轻 markdown（`` `code` `` / **粗体** / 列表）、完成回复带 Completed + 反馈条（赞/踩/复制/重新生成）、"N files changed +X -Y" diff 卡（可展开文件列表）、图片附件 chip、Artifact 卡。
- **Artifacts 托盘 + 产物预览面板**：composer 上方一排 Artifacts 卡片（markdown / web / image / diff，按 kind 配紫色图标）；点卡片在右侧打开**产物预览面板**。当前 browser prototype 与 official projection boundary 对齐为 metadata-only：不从 projection 读取/渲染 markdown、iframe、image、diff、URL 或 source raw body/ref；只展示 Host safe text fetch、Host sandbox preview intent、projected paths/size 与 mock Console Logs disclosure。
- **右栏（三元切换）**：打开产物时为产物预览面板（宽 460）；否则优先展示只读 Station `TaskGraph` projection（按当前 task 的 `projectId` / graph node 归属选中 project），没有 project projection 时才 fallback 到 legacy Todo + Context（token 用量条 + Files/Other 标签的触达文件）。Official legacy Todo fallback 折叠时会显示剩余 Station todo projection 数量，避免误以为只存在当前可见条目。Applet 只消费 `workspace.projects[].taskGraph` / legacy todo projection，不调度、执行或重排节点。
- **富输入框**：斜杠命令 / 图片附件 / 模型选择器（openrouter-3o…）/ 发送。语音输入暂不展示。

## Runtime / Projection 接入骨架

原型已从“Page 直接改 mock state”收敛到一个可联调边界：

- `src/runtime.ts` 定义 `AtelierRuntime`，这是 UI 和未来真实后端之间的唯一边界。
- `src/projection.ts` 消费当前 `atelier-projection/v0` product-unit contract 的 generated constants，定义 browser prototype adapter 的 projection snapshot / patch / method 类型视图；它不是一套独立草案协议。
- `src/bridgeRuntime.ts` 定义 bridge-backed runtime，后续可以接 Station、Tauri command 或 applet-sdk。
- `src/appletBridge.ts` 定义 applet-sdk / Web Host 适配器，把 `sdk.invoke('atelier.*')` 和 host event 转成 `AtelierRuntimeBridge`。
- `src/runtimeBootstrap.ts` 定义入口 runtime 选择：`sdk.runtime === 'lynx' | 'web-host'` 时创建 bridge runtime；`standalone / unavailable` 时回退 `createMockAtelierRuntime()`。
- `createMockAtelierRuntime()` 仍使用 `src/mock.ts` seed 数据，但所有状态变更都通过 runtime 方法发生。
- `src/Page.tsx` 只消费 `AtelierRuntimeSnapshot`，新增任务、发送消息、决策选择、归档 / 删除、模型切换都调用 runtime；如果 runtime 提供 `subscribe`，Page 会订阅 projection 更新。Page 已显式区分 `loading / empty / reconciling / degraded / disconnected / auth-denied / error / ready`，断连、权限拒绝、投影同步中和降级状态不会伪装成“无任务”。
- 真实联调时，`src/main.tsx` 会通过 `createAtelierRuntimeForEnvironment()` 自动装配 `createBridgeAtelierRuntime()` + `createAppletSdkAtelierBridge(sdk)`，对接已登记的 `atelier.*` runtime methods。
- UI 期望拿到的是 projection snapshot：`TaskList`、`ProjectProjection[]`、`StreamBlock[]`、`TodoProjection`、`ContextProjection`、`ArtifactProjection`、`GateProjection`；不要让 applet 直接解析裸 orchestration event。`workspace.projects` 是 Station 投影出的只读 Project/MilestoneTree/TaskGraph/Policy/Defect 视图，供后续插件 / 详情面板消费；默认对话优先界面不因该字段回退成项目管理看板。
- Station 已有第一批真源接口：`POST /sub-agent/agent/atelier/workspace/load` 和 `POST /sub-agent/agent/atelier/project/create-from-goal`。
- Desktop applet gateway 已开放最小 `atelier` capability / service surface：official workspace load 走 Station-bundled `atelier` service binding（`sdk.network.request({ service: 'atelier', path: '/v1/workspace' })`），project create / message / escalation / task lifecycle 也走 `/v1/...` service path；provider discovery、feedback、workspace open、artifact body/preview 与 projection event subscribe 保持 Host capability。
- Projection 增量事件 topic 为 `atelier.projection.event`，Desktop gateway 会把 Station `/agent/events/subscribe` SSE 转成 `AtelierProjectionEvent` 并放入 applet event outbox。

### Projection 契约纪律

当前 projection 是 `atelier-projection/v0` product-unit contract 对齐下的联调契约，不是跨版本生产稳定协议。为避免 TS / Rust / Go 三边结构漂移，后续每次改 projection 字段或 patch kind 必须同步检查：

- TypeScript：`packages/prototypes/desktop/applets/atelier/src/projection.ts`
- Rust Desktop gateway：`apps/desktop/src-tauri/src/application/applets/mod.rs` 中 `station_event_to_atelier_projection_event`
- Go Station projection：`apps/station/app/subserver/agent/service/atelier_projection.go`
- Manifest / capability：`apps/applets/atelier/applet.manifest.json` 与 `packages/applet-contract/src/capability.ts`
- Docs：本文的 Runtime method 与联调约定

`apps/applets/atelier/contracts/atelier-projection.contract.json` 是当前 `atelier-projection/v0` 的 product-unit machine-readable contract，覆盖 projection version、event topic、Host capability methods、Desktop gateway actions、patch union 与 replay metadata。P2-06 已从该文件生成 `atelier-projection.schema.generated.json`、official frontend `projection.contract.generated.ts` 与 browser prototype `projection.contract.generated.ts`，并新增正式 projection proto `model/domain/atelier/v1/projection.proto` 及 Station Go / Desktop TS 生成物；JSON contract 继续负责 Host/Gateway 方法与 forbidden actions，proto 负责 snapshot/event/patch 类型锚点。official reducer 与 browser bridge runtime 的 patch apply switch 现在带 `assertNever(patch)`，`atelier:projection-contract-gate` 会 exact 比对 contract `patchKinds` 与两侧 non-snapshot handler cases，避免新增 patch kind 只出现在 parser/type 中却没有 projection consumer 行为。当前仍不能把 `atelier-projection/v0` 宣称为跨版本稳定协议；只能宣称“当前三端实现由 product-unit contract + formal proto + generated schema/TS constants + gate 对齐”。当前 gate：

```bash
pnpm run atelier:projection-contract-gate
pnpm run atelier:bridge-runtime-gate
pnpm run atelier:desktop-bridge-gate
pnpm run atelier:desktop-typecheck-gate
pnpm run atelier:prototype-gate
pnpm run atelier:official-frontend-gate
pnpm run atelier:official-frontend-build-gate
pnpm run applet:atelier-desktop-injection-gate
pnpm run atelier:controlled-gates
pnpm run atelier:real-product-gates
```

`atelier:projection-contract-gate` 读取 product-unit contract，先执行 `atelier:projection-codegen-check`，再检查 formal projection proto、Station Go / Desktop TS proto 生成物、prototype TS、official frontend guard、Go Station projection、Rust Desktop gateway、manifest 与 shared capability registry 没有明显漂移。`atelier:bridge-runtime-gate` 执行真实 TS runtime 逻辑，覆盖 snapshot/event guard、重复 event 去重、同 scope 过期 seq 拒绝、snapshot 与非 snapshot capability 的异步错误状态映射（`auth-denied` / `disconnected` / `error`），以及非 snapshot capability 成功后恢复调用前 runtime status。
`atelier:desktop-bridge-gate` 复用 Desktop applet bridge/lifecycle 测试（`apps/desktop/src/applet/*.test.ts`），覆盖 `<lynx-host>` Host command side-effect 剥离、manager-owned Gateway session lifecycle、Kernel-owned pause/resume 与 applet runtime adapter 行为；该 gate 仍是本地 controlled runtime test，不证明真实 Desktop Host + Station + applet E2E。
`atelier:desktop-typecheck-gate` 运行 Desktop app TypeScript check（`pnpm --dir apps/desktop run prebuild:check`），覆盖 Desktop applet Host/page wiring 的类型一致性；它不证明真实 Desktop runtime 行为。
`atelier:prototype-gate` 构建 browser prototype（`packages/prototypes/desktop/applets/atelier`），作为 prototype sync 的可重复本地证据；它不证明 official Lynx runtime 或真实 Host 渲染。
`atelier:official-frontend-build-gate` 构建 official Lynx frontend bundle（`apps/applets/atelier/frontend/dist/main.lynx.bundle`），证明 official applet frontend 当前可打包；它不证明 Desktop 注入、Host bridge 或 Station service runtime。
`applet:atelier-desktop-injection-gate` 执行 official applet static packaging / Desktop injection / manifest integrity / service binding 校验，证明构建产物可被 Desktop dist registry 静态识别；它不启动真实 Desktop Host、Station service 或 product window。
`atelier:controlled-gates` 聚合上述 controlled gates，并追加 Desktop TypeScript check、browser prototype build、official frontend `tsc --noEmit`、official Lynx bundle build 与 Desktop injection static gate，作为进入真实 E2E 前的本地非 E2E evidence suite；它仍不证明真实 Station/Host/product window 链路。
`atelier:real-product-gates` 当前聚合 Atelier real-product workspace/replay gate、normal product-window gate、cross-restart cursor gate、human-decision/live-resume gate、artifact/gate product-window gate 与 blocking-gate recovery variant gates：workspace/replay gate 启动 sqlite-backed Station gate server，经 Desktop Gateway `network.request` / `atelier.events.subscribe` 访问 Station-bundled Atelier façade 与 Station EventStreamService；normal product-window gate 启动 packaged `peers.atelier` Desktop product shell，通过 external Station proxy 断言 official applet 在真实 Desktop product window UI 内完成 `GET /v1/workspace` service binding 到 `/applets/atelier/v1/workspace`，再通过 product-window E2E launch options 触发 `atelier.events.subscribe`，等待 `/sub-agent/agent/events/subscribe`，并用 gate server replay probe 证明受控 pre-replay / post-first-replay SSE close 后的 cursor replay 序列 `afterEventSeq=0 -> []`、`afterEventSeq=0 -> [1]`、`afterEventSeq=1 -> [2]` 到达 Station EventStreamService，同时覆盖 applet-side rendered state assertion after projection event delivery；cross-restart cursor recovery 由独立 product-window cross-restart gate 使用同一 storage root、不同 applet session 证明持久化 cursor 恢复；artifact/gate gates 覆盖 Station-produced artifact/gate projection、Host-rendered preview surface descriptor、`rerun_failed_node` 与 `accept_risk` / `continue` / `cancel` recovery variants。它仍不证明任意网络故障矩阵、真实 executor/provider recovery completion、Host rich artifact renderer / Console Logs / attachment Host Storage 或完整 Host+Station+applet E2E。

GAP-01~07 的 Project 族 projection 已进入 Station JSON mapper 与 official/prototype guard：`workspace.projects` 包含 `ProjectProjection`，并从 Station-owned `CollaborationTask`、`TaskNode` 与 durable events / query durable outbox transaction 内从 task/node/gate/blocker/risk/predicate/memory evidence 推进并写入 `agent_project_states`；同一 runtime 还会 materialize `agent_atelier_milestones`、`agent_atelier_task_graph_nodes`、`agent_atelier_task_graph_edges`、`agent_atelier_policies`、`agent_atelier_policy_rules` 与 `agent_atelier_defects`，`LoadWorkspace` 优先使用这些 Policy/Defect。`ProjectCompletion.noOpenBlockers` 已从旧的 blocker 数量判断推进到 `Blocker.state` 谓词：blocking gate failed 产生 `open` blocker，gate-blocked human decision / later passed gate result 可把同一 gate blocker durable outbox 同步 Project/Milestone legacy state payload、blocker/risk lifecycle 与 acceptance predicate registry/verdict snapshot，随后刷新 deterministic predicates 并推进 ProjectStateMachine；`LoadWorkspace` 优先使用这些 Station-owned persisted records，旧 meta/event-derived projection 仅作为历史数据 fallback。Station deterministic `AcceptancePredicateEvaluator` 可计算 no_open_blockers、data-model blocker quantifier、root milestone/task accepted、residual risks、goal owner signoff、memory candidates、`gate.passed`、`gate_result(g).passed`、blocking gate aggregate 与 L2 human signoff aggregate；root milestone accepted 不读取旧 ProjectState 自证，避免 stale-cycle。Milestone 只投影 `acceptancePredicateIds`，ProjectCompletion 只投影聚合布尔值，Applet 不获得 predicate registry、evaluator 或 ProjectStateMachine 执行权。TaskGraph node 的 `artifactIds/gateIds` 由 Station-owned `TaskArtifact` / `TaskGateResult` indexes 按 `step_id` 回链；缺少 node 归属的 artifact/gate 仍保持 task-level projection，避免 UI 猜测 evidence 归属。这些字段仍然只是 projection `atelier:official-frontend-gate` 执行 official Lynx applet 的 projection guard / reducer 逻辑，覆盖 `atelier.projection.event` 解析、重复 event 去重、同 scope 过期 seq 拒绝、`stream.append` block 去重，以及 `artifact.upsert` / `gate.upsert` patch 应用；它只证明前端 projection consumer 的本地行为，不证明真实 Host + Station SSE 已跑通。

### Runtime method 草案

| Method | 用途 |
|--------|------|
| `GET /v1/workspace` service binding | 加载当前 workspace projection snapshot |
| `atelier.project.createFromGoal` | 从用户目标创建 Atelier project / task |
| `atelier.message.send` | 向当前 task 追加用户输入 |
| `atelier.escalation.resolve` | 回写决策卡选择 |
| `atelier.task.setStatus` | 更新左栏收纳态：active / archived / deleted |
| `atelier.task.purge` | 彻底删除回收站任务 |

`AtelierRuntime.setModel()` 只更新 composer 本地偏好，不走 Host / Station capability。

### applet-sdk 接入草案

真实 applet 侧不直接 import Desktop `api` 或 Tauri `invoke`，而是把 applet-sdk 的 `sdk` 适配成 `AtelierRuntimeBridge`。当前 `src/main.tsx` 已使用 `src/runtimeBootstrap.ts` 做环境切换，等价于：

```ts
import { sdk } from '@peers-touch/applet-sdk';
import { MOCK } from './mock';
import { createAppletSdkAtelierBridge } from './appletBridge';
import { createBridgeAtelierRuntime } from './bridgeRuntime';
import { toProjectionSnapshot } from './projection';

export const runtime = createBridgeAtelierRuntime({
  bridge: createAppletSdkAtelierBridge(sdk),
  initialSnapshot: toProjectionSnapshot(MOCK),
});
```

联调约定：

- 命令：`sdk.invoke(method, payload)`，其中 `method` 使用上表的 `atelier.*` 点分方法名。
- 启动：Host adapter 为 `lynx` / `web-host` 时走 bridge；`standalone` / `unavailable` 时走 mock，保证 prototype 可以继续独立设计评审。Host 模式的初始 snapshot 必须是空 projection，不允许展示 mock 任务后再被真实数据覆盖。
- 权限：`@peers-touch/applet-contract` 已登记 `atelier.*` capability methods；运行时 manifest 草案位于 `apps/applets/atelier/applet.manifest.json`。
- 订阅：如需自动连接 Station SSE，可通过 URL 参数 `agentId`、可选 `taskId` / `afterEventSeq`，或在页面注入 `window.__ATELIER_PROJECTION_STREAM__`，由 `runtimeBootstrap` 传给 `createAppletSdkAtelierBridge()`。
- 返回：每个命令先返回完整 `AtelierProjectionSnapshot`，保证 UI 能从任意一次操作恢复一致状态。
- 增量：host 通过 `atelier.projection.event` 推送 `AtelierProjectionEvent`，其中 `patch` 使用 `AtelierProjectionPatch`；bridge runtime 会按 event `id` / `seq` 幂等消费，并在 `stream.append` 时按 block `id` 去重，抵御 SSE 重连回放 / outbox 重投。
