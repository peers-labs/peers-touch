# 抽屉集：应力、导轨与空间守恒

这是一套窗框设计，适用于 Desktop 原型和实际客户端里的目录、会话、详情、
线程以及它们的标题、工具、消息、输入区域。配色已确认；完整原型及原生
体验仍需对应评审与证据，代码接入不替代原生验收。

## 当前实现所有权（2026-11-16）

本轮 Desktop 落地使用 `packages/ui/web/src/drawer-assembly.ts`、
`use-drawer-assembly.ts` 和 `drawer-resizer.tsx` 作为唯一几何、运动与手势
所有者。原型 `ChatFeature` 和实际 `SocialChatPage` 都消费该实现；旧原型
私有模型和实际720/960布局已移除。数值归 `packages/ui/tokens` 的
`geometry.chatRail`、`geometry.drawer`；原型和 Native 的三个结构底色归
`structural-surfaces.ts`，不再把控制填充 `subtle` 当二级结构色。

Native 的业务会话/详情/线程意图继续归 Social Runtime/store；页面只适配
展示导航。Back不清会话选择；主工作实例保持挂载。内叶只保留当前任务，
线程接收保留的根ID以维持回程和草稿。`TextArea`承担输入增长和预算重测，
页面仅观察实际高度变化通知原有尾部锚点。本文记录实现事实，原生窗口
事件、视觉和性能仍需现源码观测，不使用历史原型证据升级状态。

人的工作位置应当连续。窗口伸缩改变约束，手拉分隔线改变偏好，选择对象改变
任务；三种输入不能混成同一个「变窄」开关。界面中的物理类比必须落实到
连接关系、受力入口、传递顺序、止挡、回程与操作现场，而不是只借一个弹簧曲线。

## 结构和承重

| 层 | 物理角色 | 承担什么 | 不承担什么 |
| --- | --- | --- | --- |
| 一级导航与外框 | 固定底座，60px 导航轨 | 全局定位、固定设置/通知锚点 | 不随目录拉伸，不改为横排 |
| 二级目录 | 外导轨上的有限纸面 | 找到会话/联系人；保留列表位置 | 不吸收无限窗口余量，不把文字拉成竖排 |
| 三级会话 | 主工作抽屉 | 阅读、选择、写作、发送和恢复 | 不自行监听整个窗口断点 |
| 详情/线程 | 主抽屉拥有的内叶 | 当前对象的附属任务 | 不越过父层向一级、二级借独立一列 |
| 菜单/对话框 | 浮层 | 短暂决策；既有 primitive 负责碰撞和焦点 | 不冒充承重导轨 |

材质服务于空间归属：连续的中性底座、目录纸面、阅读纸面；pine 仍只标记
身份、当前位置与连接。用户已于2026-11-16确认 **A · 矿灰纸白**：
同一中性底色，向内容逐级提亮。配色唯一决定见
[结构底色宪法](./north-star-frame.md#a--矿灰纸白结构底色宪法已确认)；
应力模型与尺寸/运动参数仍是候选，配色确认不替代其评审。
同一导轨的标题、正文、写作台共享位移和可用宽度，不能各自弹跳。

## 谁先动，取决于施力入口

「外层先开」不是普遍物理定律。本设计明确指定连接与阻力：

- **框架伸缩**是改变抽屉集外部约束，不等于拉任一把手。目录完整64轨与
  工作最小200预算先保住，其后先释放目录到展开偏好；
  目录到位后余量归工作区。480是理想阅读宽度，不占用刚性预约。
  不足264舞台时先保持完整目录入口，工作湾继续收紧；返回可恢复有限完整目录。
- **目录分隔线**连接外导轨，直接拖动时只有该导轨跟手；主工作区接收剩余
  空间。到止挡才结算，不在指针移动途中跳到另一个稳定宽度。
- **选择会话**解锁主工作抽屉，从右侧同一导轨抽出；选择另一个会话更新
  内容，不重新播放整页入场。
- **打开详情或线程**解锁内叶。父层已经打开才能开内叶；返回首先收内叶，
  再次返回才收父层。快速重复返回也先将内叶送到止挡。

主动操作提供意图；自动适应改变显露量。展开偏好与临时收起是两个状态；
缩窗不会写入64偏好。扩大框架到足以容纳展开目录时，释放临时收起，
恢复记住的展开宽度；目录仍有有限止挡，不撑满整个舞台。

### 状态机修正评审（2026-11-16）

三项已复现的缺陷：持久64导致宽窗不展开；200共同门槛把170显露的姓名
和工具一起藏掉；对隐藏纸面结算使可见边缘停在80附近的中间态。
修正归共享所有者，不增加宿主CSS断点或生产mouse事件回退。

目录状态为 `rest=compact|expanded`，运动为 `idle|dragging|settling`。
稳定宽度分两段：64是唯一紧凑止挡；**160..360是连续可用带，带内每个释放
宽度都是静止态并按原值持久化**（160取自完整轨头工具组的占位预算）。
64..160之间是无稳定位的间隙，只在释放时按末段方向吸附：收向64或推向160；
无方向输入按间隙中点择近。旧64/中间值缺少展开信息，读入默认300。
手势开始保存完整rest与展开偏好，并从可见坐标跟手。压缩框架的可达上限
不足160时，临时姿态可以更小，但不覆盖记住的展开偏好。取消从当前绘制
坐标回到开始前的rest，不提交。
重抓接续当前坐标；框架改变取消手势并按新约束结算。展开偏好可以在明确
展开操作中更新，环境伸缩不持久化。

动画完成后显式进入idle；RAF和到期计时器共用同一结束动作，后台暂停RAF
不能留下永久中间态。reduced motion直接到位。框架扩大时，仅在新空间足以
恢复完整展开目录才释放临时收起，恢复也从当前姿态开始。

身份行预算由36头像、10间距、两侧8内缩及至少72文字计算，外层留白一并
计入后为144。轨头独立预算为160：两项28图标tab、8轨内缩、两个28动作、
两个8间距及外层留白。标签是否能放下仍归Segmented。144..159显露姓名与
预览，轨头保留菜单；达到160显示两个tab、搜索、新建，文字够放再恢复。
联系人申请等长任务保持原有回目录展开入口。

## 一次分配，全体消费

以下参数已接入共享 token；接入不代表原生体验已经完成验收：

| 量 | 候选值 | 理由与评审条件 |
| --- | --- | --- |
| 目录展开偏好 P | 默认300；160..360 连续可取 | 与临时compact止挡分离；160是完整轨头工具组仍可容纳的最小稳定宽度，360是有限止挡，超长名称仍省略/提示 |
| 工作阅读预算 R | 480 | 两侧24留白与432阅读/写作空间；它是软预算，不能成为窗口最小宽度 |
| 工作最小/可用预算 M/U | 200/280 | 紧凑标题的返回、名称、菜单与留白需要约200；280容纳日常写作。与64目录共同承压，不硬占480 |
| 主工具组紧凑边界 | 工作湾400 | 整组工具转入可达菜单，返回和身份仍完整 |
| 消息工具侧放预算 | 工作湾720 | 不足时保留气泡下方固定工具槽，元数据与Retry独占下一行，hover不改行高 |
| 目录身份行/轨头预算 | 显露144/160 | 身份行和轨头分别按完整元素占位恢复；不共用一个compact开关 |
| tab文字预算 | Segmented实测 | 标签不够放时保留两个图标入口；够放即恢复文字，不使用另一条300px门槛 |
| 导航/目录头像与目录行 | 36px/6px圆角；行48px；紧凑选择面48px方形 | 展开行垂直内缩4px；紧凑头像外留6px；行面紧凑圆角、1px选中标记；头像圆角不改控件圆角 |
| 窗框底座露出 | 1px | 与一级矿灰连续；输入区域独立使用8px外缩 |
| 内叶宽度 | W<800占满工作湾，否则320 | 480阅读余量+320内叶才能停靠；同湾打开，不推目录 |
| 写作台高度预算 | min(280,max(96,(H−52)×0.58)) | 标题52；短高时消息区仍有空间，输入行数按预算缩减，附件区独立滚动 |

唯一输入是父舞台的真实宽度 S，不包含一级导航和外框。几何分配：

```text
当前导轨目标 T = rest=compact ? 64 : P（P为160..360内任一持久宽度）；dragging/settling使用当前绘制宽度
目录纸面 C = min(S, T)
完整目录入口 K = min(S, 64)
目录可达上限 A = min(S, max(64, S - M))
目录显露 E = min(C, A)
主工作湾 W = S - E
框架压力 q = (C - E) / C，C=0 时 q=0
关闭止挡 B = max(C, E + q × W)
主抽屉位置 x = E + (1 - n) × (B - E)，n 为开合进度
内叶宽度 D = W<800 ? W : 320，沿自身右侧导轨运动
```

因此 E+W=S，每扩大1px，E最多扩大1px；显露到P后不再增长。
H与S从同一个父舞台快照读取。内叶占满湾时是对象任务覆盖；
宽湾停靠时保留父内容作上下文，父任务仍暂停输入，不冒充同时可编辑的两栏。
主工作湾不随内叶开合缩宽，消息气泡不会跟着内叶的每帧运动重排。
目录纸面保持自己的自然宽度，它可以被主抽屉遮住；其字形、头像和按钮不
按压力缩放。关闭会话时目录恢复显露，绝不临时变成 S 宽的全舞台列表。
同一基础几何用于有选择、无选择、空、等待、失败状态；选择只影响开合姿态。

框架压力连续地缩短/释放行程。q=0时主抽屉已驻留在工作湾；
关闭止挡始终让出整张有限目录纸面。这样展开/并列之间无需另一个720px跳变。

## 运动、取消与生命期

`ChatFeature` 的 assembly controller 拥有一次父级测量、偏好、主动拖动、
主抽屉和内叶意图，输出同一几何快照。子区域不得再用独立 viewport
`matchMedia` 决定开合/宽度。首测在 layout phase 完成，ResizeObserver
通知必须在下一次绘制前发布宽高快照；禁止 passive effect 二次 clamp。
Portal → Gallery → Provider → 窗框 → 工作湾必须逐层传递有限高度，
不能内部按320排版、上层却按内容撑到336再把底部截断。

手拖无缓动；松手在160..360可用带内保持释放处的精确宽度，只有落入64..160
间隙时才按末段方向吸附到64或160，压缩框架下吸附到当前可达的对应止挡。
Esc、pointercancel、失去捕获恢复此次手势开始前的rest和展开偏好；pointerup才提交。
重新抓住正在到位的导轨，从屏上位置接续。窗口压力变化取消当前手势，
不提交被环境挤出来的宽度。
共享把手拥有10px完整命中区域；靠舞台最右缘时命中区域向内移，边界线仍在
目录右缘，不能让最大止挡上的把手被裁掉而无法反向抓取。
把手在pointerdown中显式focus（为了手势内的Esc和后续键盘微调），而程序化
focus在Chromium与WebKit都会命中`:focus-visible`；因此组件自行管理输入模态
（`data-keyboard-focus`），指针获得的焦点保持视觉静默，只有键盘到达的焦点
才点亮分隔线。命中条上禁止任何盒形焦点环（outline/inset shadow）——全高
10px条上的盒形环会呈现为两条贯穿全高的竖线；唯一视觉指示器是那一条1px分隔线，
hover、dragging与键盘焦点共用它，blur后熄灭。
分隔线位于当前可见目录右缘；受压不禁用。拖动从该屏上边界起步，先算
目标显露，直接操作可达边界，不再逆解隐藏纸面的偏好；每个可达指针像素对应边界像素；越过有限
止挡才停止。键盘也基于可见边界，ARIA报告当前可见范围。无移动抓放不
提交；返回时分隔线随完整纸面右缘，而非留在先前受压显露处。

主抽屉和内叶使用共享 `motion.navigation` / `motion.ease.drawer`：
单调行程、渐进停稳、不越过止挡、不撞边回弹。该曲线是候选运动表达，
不是声称模拟了真实质量/刚度；没有阻尼参数时不得自称「临界阻尼」。
反向从当前绘制坐标接续，旧动画必须取消；环境伸缩直接分配，不追赶旧尺寸。
reduced motion 立即到位，并保留相同任务和返回语义。

多股力的仲裁：框架变化立即重新分配，并取消尚未提交的手拖；目录自动
到位可与主抽屉开合同时发生，两者以当前姿态合成，不排队追赶旧几何。
重新抓住目录只取消目录的到位过程，不重启父任务；主抽屉反向只取消
自己的旧行程。父层尚未到位时拒绝内叶意图，换会话取消旧内叶。
“不反弹”指几何约束恒定的一段行程内不越界、单调到位；同时缩窗产生的
反向屏幕位移属于新的外力，不能拿单调n冒充屏幕坐标全程单调。

返回与选择分离：收主抽屉保留会话、草稿、回复/编辑目标和阅读位置；
删除对象才清除业务对象。窗框、目录、主抽屉根始终保留。内叶按需首次挂载，
关闭回程保留当前内叶实例；不同内叶任务切换只保留有界的当前实例，
不得预先挂载所有详情/线程。隐藏区域停用输入；焦点使用 preventScroll
回到源入口，消息定位只改变消息 viewport 的 scrollTop。

工作现场由 `ChatFeature` 持有的会话桶保存：普通草稿与未提交编辑文本
分别保存，回复目标、附件进度/计时器、已录音blob、光标选择、线程草稿与
回复、消息ID+偏移锚点都随会话身份恢复。同一时刻只保留当前会话DOM。
批量模式覆盖写作台但不卸载它；换会话退出批量选择。Back不销毁对象，
删除会话或关闭页面才清理桶内计时器与URL；发送转交消息的URL继续由
会话持有。正在采集的麦克风随会话DOM退出取消；迟到的授权不再启动采集。
已有录音预览保留；发送录音不丢弃另外写好的文字或附件。
阅读区只有原先在尾部才跟随新消息/typing；否则按消息锚点恢复。

## 元素集的压缩合同

| 区域 | 随框架联动的内容 | 必须留住的动作 |
| --- | --- | --- |
| 目录 | 轨头、分区、身份行、搜索、申请队列 | 完整头像入口；紧凑轨头菜单；长任务可回目录展开 |
| 会话标题 | 名称、状态、通话、详情、返回 | 返回、名称、完整工具菜单；次要动作整组收纳 |
| 消息阅读 | 气泡、附件、时间、状态、Retry、动作锚点 | Retry整体可达；文本换行；只有消息区纵向滚动 |
| 写作台 | 回复、附件、输入、工具、发送 | 输入与发送不出框；工具组换行或收纳，不能裁半个按钮 |
| 内叶 | 标题、关闭、详情/线程正文、线程输入 | 关闭始终完整；正文独立滚动；父层没有被它挤宽 |
| 外框 | 一级导航、设置、通知 | 固定轨与固定锚点；短高度保留可滚动的导航组 |

文字可省略或换行，导轨遮挡是空间关系；交互控件必须作为完整单元保留或
转入菜单。舞台不足64时整组目录停止绘制与输入；紧凑轨头和头像在完整64轨内对齐。
叶任务覆盖的父任务停止输入，避免焦点进入被盖住的发送或工具按钮。
绘制回程和输入资格分开：被盖住或尚未到位的区域同时inert与aria-hidden，
只在到位且命中测试确认入口可见后恢复焦点。原入口不存在时回到目录轨头
或父工具入口。菜单/对话框先消费Esc，再到内叶、主抽屉，最后到Portal全屏。
内叶回程的占位尚未归零时，目录、分隔线和父任务仍暂停输入。
删除/隐藏当前会话直接撤销该任务的全部导轨与内叶内容，回到可用目录；
会话删除对话框先由primitive释放inert，再恢复目录焦点。
无 hover 的设备仍可通过菜单/键盘访问所有动作。
会话行只保留一个三个点动作入口，绝对锚定在行自身的右下角，不随轨道宽度
漂移，统一收纳 Pin/静音/已读/隐藏/删除；静止态 `pointer-events:none` 且
不可见，不得吞掉行点击或持有焦点。Pin/静音的状态标记（tag）静止时位于
预览行（下方一行）右侧、时间之前，绝不上移到名称行；hover 与
`:focus-within` 两种输入模态下合同一致：时间与 tag 隐藏，三个点 tile 接管
右下角，预览行让出约36px单按钮车道并在车道前省略，文本与按钮永不重叠。
Pin 是状态切换而非恒动作用途：已置顶的会话，上下文菜单必须呈现 pin-off
图标和「取消置顶」标签。
轨头 Segmented 的挤压必须是阶跃而非连续形变：带标签岛 → 固定28px图标岛
（图标尺寸不随轨道缩放，空间不足时岛内横向滑动、滚动条隐藏）→
不足160px工具预算时整体换成单个紧凑菜单图标；轨头纵向高度在所有状态恒定。

短高度并非把全部内容同比压小：标题、关闭、发送作为完整动作单元保留，
展开输入按预算减少行数；回复/附件/错误说明进入有界附件区纵向滚动。
W<400时写作工具整组占一行，输入、展开、发送另占一行；批量工具整组换行。
图片仍保持媒体比例，消息区接收剩余高度。
消息工具侧向空间不足时进入气泡下面的固定槽；即使未hover也保留槽位，
出现工具条不会推挤相邻消息，不能让下一条消息的工具条盖住上一条Retry。
隐藏工具条不接收指针；键盘进入消息工具仍按既有focus-within显示。
写作台的展开/收起必须可逆：TextArea 的 auto-grow 会写入显式 inline height，
仅靠 ResizeObserver 无法捕捉「约束变小但盒子未变」的收起动作（展开因 min-height
强制撑大盒子而恰好可用，造成只能放大不能缩回的不对称）。因此 primitive 自行
记录计算后的 min/max-height 约束签名，约束一变化就重新测量，使展开与收起
走同一条高度合同；调用方无论用行数 props 还是 CSS 约束变量驱动，往返后都回到
与内容匹配的高度，多次往返无漂移。

## 决策、代价与边界

选择有限目录+共同承压，代价是某些宽度使用紧凑头像目录，紧凑轨头
需要一次菜单操作；长联系人申请任务应回到完整目录执行。固定720
单页切换、百分比放大目录、每个区域各设断点都不能保证该守恒关系，
故不保留为并行的活动布局路径。

这些数值和空间安排接受完整原型评审；若长任务或本地化需要改变预算，
改 policy 并重跑全集，不在某个按钮上补负边距。原型确认之后，生产仍需
按正式运行时重做并验收，不以浏览器结果证明 native 窗口事件。

合同冲突记录：`craft-quality.md`的整面位移禁令与`tokens.md`、
`chat-layout-contract.md`的窄会话导轨要求不一致。本稿提出精确的抽屉例外：
同一持久根沿已声明导轨运动以表达空间所有权，不能重挂载内容或用fade遮错。
该例外及360/480/320、松手结算、取消回滚均仍是候选，需合同所有者评审，
不能靠本稿、浏览器通过或旧确认声明自动晋升为已接受生产规则。

## 证据与验收

源码事实：原型 `ChatFeature` 自己监听720，CSS另有720布局；宽度偏好独立。
基线浏览器观测：P=420时757舞台的目录仍420；719/721两像素边界出现
299px目录跳变。它证明了原型的几何缺陷；尚不能声称捕获了用户 native
录像中的每一帧。
