# 飞书助手 — 交互合同

> **Status**: draft
> **Version**: v1.3
> **Created / Updated**: 2026-10-18
> **Owner**: Agent / Channel

## 入口与界面边界

入口固定为全局 `Settings → Channels → Lark`。`Bots` 与 `Lark` 是同级入口。
Lark 根页面呈现连接名单；进入详情后只呈现当前连接的连续工作面，
不再按消息、群聊或工作拆分标签。

名单回答“有哪些身份、哪个是默认、各自是否可用”；详情回答“应用连接是否可用、
是否配置默认响应 Agent、下一步是否需要用户动作”。高级能力按意图进入聚焦子页面，
返回后仍是同一连接。

## 首次连接

空名单以 Lark 应用连接为主语。点击 `Add Lark connection` 后在当前页面打开
一个全新空白 Dialog；不能带入上一次新增会话、已有连接或所选 Agent 的字段。
Dialog 用紧凑 Tab 提供两种对称方式：

- `Create managed app`：填写应用名称与平台，然后扫码取得应用身份。
- `Use existing app`：填写平台、App ID 与 App Secret，校验后取得应用身份。

两条路径都只完成 Lark 应用身份和消息链路，生成同一种连接，不在创建流程中选择
或创建 Agent。完成后追加连接并进入详情；默认响应 Agent 在详情中按需配置，
会话 Agent 仍是后续路由覆盖。处理中只展示结果级进度，不要求用户理解事件订阅
或 WebSocket。已有连接不被覆盖。

已有应用只收集必要凭据，系统统一检查身份、消息、事件和权限；缺失项合并为可执行
恢复动作。App Secret 提交给 Station 后加密持久化，不写客户端存储，也不回显。
名单入口创建新连接，详情入口替换当前连接的应用。

## 连接名单

每行展示连接名称、应用身份、可选默认响应 Agent、状态和默认标记。点击整行进入详情。
`Add Lark` 始终追加连接；默认连接可显式更换。暂停是可逆动作；
删除必须确认，且只能删除当前连接。删除默认连接后自动选择下一个可用默认连接。
移动窄窗口使用名单 → 详情返回，不隐藏并同时挂载所有连接详情。

加载中、加载失败与空名单是三个独立状态。只有一次成功读取明确返回零项时才能显示
空名单；读取失败显示错误与重试，不能伪装成“尚未连接”。

## 已连接页面

页首展示连接名称、Lark 应用身份、连接状态和简短用途说明。Agent 不作为连接身份
的一部分，也不使用 `Agent ↔ Lark` 绑定图。默认响应 Agent 是连接详情中的独立配置；
未配置时连接仍存在，但新消息不会进入默认 Agent 处理。
主要操作只有：

- `All Lark connections`：返回名单。
- `Make default / Pause / Resume`：管理该连接本身。
- `Open conversations / Activity`：进入该连接的会话和诊断结果。
- `Change`：切换整个连接的默认响应 Agent。
- `Send a test message`：输入接收人和文本，并保留发送中、送达或失败结果。
- `Make it yours`：按需打开会话 Agent、自动化或个人 Lark 授权。
- `Connection options`：健康检查、已有应用和删除。

私聊、群聊、话题、图片和文件不出现在设置中。用户在 Lark 中自然使用，
系统依据消息上下文处理；只有不支持或需要额外授权时才打断。

## 高级意图

**会话 Agent**：用户选择一个真实会话和目标 Agent。保存后只影响该会话，
不改变连接身份或其他会话。已保存偏好显示在同一名单中，可编辑、暂停、
恢复和删除。一个会话只能存在一个有效偏好；冲突在保存前明确提示。

**自动化**：用户描述触发条件和期望结果。确认页展示时间或来源、执行 Agent、
结果接收方；协议事件、调度器和投递通道由系统负责。保存后返回可管理名单，
每项可试运行、编辑、暂停、恢复和删除，并显示最近一次执行/投递结果。

**我的飞书**：仅在需要文档、日历或联系人时授权个人身份。
授权过程显示等待状态，成功后显示实际身份。Bot 连接与个人权限分离；
过期时暂停依赖个人权限的动作，支持重新授权；撤权需要确认。
敏感写入仍需可读预览和再次确认。

**已有应用**：空字段和非法 App ID 不能进入连接结果。系统先检查身份、
消息、事件和权限；缺失项形成一个可执行修复动作。检查通过后仍需用户确认
创建连接或替换当前应用，替换不清除默认响应 Agent、会话偏好、自动化和历史。

**健康与恢复**：一次检查分别呈现 Lark 身份、收发消息和默认响应 Agent。
失败时保留身份、响应配置、会话偏好和自动化，只修复缺失环节。

## 消息与结果合同

文字、post、图片、文件、引用和转发沿用消息本身的上下文关系。
图片回答需包含可核验事实；文件解析保留来源；出站文件必须可打开。
未知类型明确说明限制，不用资源 key 冒充理解结果。

执行与投递是两个状态。已完成但投递失败时仅恢复投递；
结果不明先核对，不能重新运行模型和工具。重复操作返回同一任务的当前状态。

群聊中的成员身份、话题边界和个人资料权限必须隔离。
机器人消息不得触发互相回复；任何成员都不能借用连接者的个人 OAuth。

## 中断与危险操作

关闭聚焦页面返回连接详情并恢复焦点。扫码取消回到原连接或连接名单。
会话偏好和自动化的未保存草稿在退出和刷新后保留，并提供恢复或丢弃入口；
新增连接字段只存在于当前 Dialog 会话，关闭、取消、成功或再次打开时为空。
App Secret 不写客户端持久化；Station 以加密密文持久化并在服务重启后继续使用。
暂停停止新消息并保留连接数据；删除前说明不可逆影响。
跨连接切换不得改变另一连接的草稿、Agent、授权、自动化或测试投递结果。

## 已知原型边界

扫码、OAuth、测试消息、自动化和故障恢复均为本地模拟。
原型不创建应用、不取得 token、不读取消息或工作资料。
当前覆盖多连接名单、独立详情和新增/默认/启停/删除；真实媒体、群上下文、
生产多连接运行时、国际版、暗色、完整键盘与生产 i18n
仍需独立验收。
