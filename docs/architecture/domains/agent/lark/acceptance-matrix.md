## 开通与运行

LARK-J01/J02：并发重投与进程重启，接收者只获得一次同任务结果；
人为制造投递故障后只重试已有结果，模型与副作用执行数不增长。

LARK-J03—J07：默认路径从当前 Agent 直接扫码，系统完成身份、消息和 Agent 连接；
取消、过期、失败和外部平台审批均可恢复，不要求用户预先配置名称、头像或使用方式。
自带应用先校验身份、消息、事件和权限，修复后由用户确认替换；国际版独立验证。
失败后不得新增第二应用、覆盖当前连接或丢失合法凭据。
国际版使用自己的账号和区域 API/WS，不能用飞书测试代证。

LARK-J08：当前 Agent 与会话级 Agent 偏好分别验证；创建、编辑、暂停、恢复、
删除、刷新和重启后读取一致。缺模型或运行时的 Agent 不能显示可执行。

LARK-J08M：连续创建至少两个 Lark 连接；名单、详情、默认切换、暂停、恢复和删除
均读回一致。分别在两个连接中设置 Agent、会话偏好、自动化、个人授权和测试投递，
切换与异步完成后不得串写。扫码与已有应用新增都必须追加，替换只影响当前连接。

## 消息与媒体

LARK-J09：发送包含具体事实的真实截图，模型回答该事实；
核对下载、附件准入、模型消费和接收者内容。
仅包含 image key、空附件或资源编号判失败。

LARK-J10：实际文件、post、引用、合并转发逐类输入；
文件解析保留来源，生成文档/图片/文件可由接收者打开检查。
未知类型如实提示限制。支持类型逐项登记，不推断音频、视频或贴纸能力。

LARK-J11/J12：实际流式卡片、限流退避、终态优先、降级回复；
用户询问、批准、拒绝、取消、重试、反馈、重复点击、过期和撤权。
旧更新不能覆盖终态，重复操作不能重复工具执行。

## 群协作

LARK-J13—J15：真实私聊、群聊、@、目录、主线/话题隔离、会话 Agent 偏好、
防循环和上下文回补；这些是自然消息场景，不需要在 Settings 选择“使用方式”。
两个群、两个话题、两个用户分别放入独有事实，回答不能跨范围泄漏。
成员身份、个人资料权限、成员移出、回补权限失效与恢复逐风险取证。

## 个人资料、工作和自动化

LARK-J16：两请求人分别 OAuth、按需增权、过期、重新授权和确认撤销；
界面读回实际账号身份。Bot token 不代替用户 token，旧卡片和工具动作在撤权后失败关闭。

LARK-J17：文档 / wiki / 云盘 / 联系人读取和预览。
用户 A 能读、B 无权的同一资料必须产生不同的真实结果。

LARK-J18A：文档创建/编辑含预览、批准、拒绝和产物读回。
LARK-J18B：云盘写入/移动等动作含实际目标、副作用与可打开结果。
LARK-J18C：按完整参考工具清单继续拆分；每种动作具来源、分发、
scope、请求人身份、副作用、执行链和独立接收者断言。
CLI 支持的命令族、OAuth scope 和可完成的用户动作不能混为同一清单。

LARK-J19：每个自动化保存触发条件、动作、Agent、接收方和最近投递结果；
创建、编辑、试运行、暂停、恢复、删除、实际事件、文档评论、定时、主动通知、
过窗、故障与取消在同一生命周期验证。撤权后依赖个人资料的自动化暂停。

LARK-J20：步骤、事件、投递、插件恢复与脱敏导出；
消费者切换后没有第二实现路径，秘密不能出现在证据和 UI。

## 运行条件

源身份关联 root、HEAD、未提交内容摘要、构建产物和运行实例。
真实资源至少包含飞书和国际版账号、两个用户、两个群、
图片/文件和个人资料。缺少资源只阻塞相关 Journey，不填假 PASS。
Suite scope 复用构建、服务、账户和登录；场景只 attach 和操作自身数据。
部署和共享资源操作须使用已授权 profile，不能临时启动另一个 Station。
