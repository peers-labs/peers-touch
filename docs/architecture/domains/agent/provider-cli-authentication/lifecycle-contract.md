# 模型服务完整生命周期：产品合同候选

状态：draft，2026-10-31。本文拓展本目录的账号连接草案；没有获得用户确认，
不能作为生产实现授权。用户指南与架构分开，见配套 `user-journey.md`。

## 产品承诺

管理员从一个模型服务入口完成接入、账号连接、模型验证与用户分配。
被分配的用户在 Desktop 看见可用模型，选择默认值并得到一次真实回答。
安装、保存配置、账号连接、发现模型、验证调用和分配权限分别有事实依据。
任何一步未完成，页面明确显示缺什么、谁负责、下一步在哪里。

普通用户不需要学习 Provider、协议、CLI 参数、环境变量或凭据目录。
Dashboard 管理员也不需要在多个独立工具之间猜测步骤。

## 现场与源码事实

- 当前 Dashboard 把安装区放在 Provider 编辑器之外；编辑器分开保存配置、
  Credential、Models 与 Grants，没有串联的下一步。Codex 的现有页面没有
  登录、检查连接、试用模型入口。安装检查只证明二进制存在。
- `apps/desktop/src/runtimes/agentCapabilityRuntime.ts:120-134,203-212`
  在缺少本机 capability session 时以约一秒间隔调用整个能力图加载。
  `:28,323` 的周期调和会再次进入这条路径。运行日志观察到连续 warmup。
- `apps/desktop/src/components/ModelServiceTab.tsx:30-40`
  使用 Agent 共享 loading 状态，在空模型列表刷新时替换整个内容。
  因此本机工具探测与模型消费页面的加载状态存在错误耦合。
- 原生窗口的 12 秒、24 帧被动采样只捕获到稳定空态，未捕获用户描述的
  闪烁帧；不能把这次采样写成视觉复现成功。源码和连续请求日志支持上述
  刷新链路，不证明每次刷新均有可见闪烁。
- `catalog/providers.default.yaml:234-347` 中 Codex/Claude 的 `Default`
  是静态 adapter 选择；Cursor/TRAE 有模型发现命令。静态目录或发现成功
  都不能证明某账号可调用某模型。
- `ProviderModelDiscoveryService.Discover` 使用 Owner 与私有状态目录；
  `RuntimeModelCatalog` 按 Owner、Provider 与配置版本隔离。扩展必须复用。
- 当前 Codex 设备授权在现场启动失败；Claude 部分账户存储隔离未证明。
  此候选不将这些厂商的真实授权标记为已完成。

## LC-01 信息架构

Dashboard 一级导航使用“模型服务”。默认列表每行展示：
服务名称、来源类型、当前状态、已分配人数、当前下一步。
内置 CLI 与 API 都在此列表；不再让用户先从另一个安装区发现 CLI。

“添加模型服务”先选择已注册供应商，再呈现该类型真实需要的输入。
CLI 使用已注册 adapter，安装位置为当前 Station 节点，安装后原行变为
“连接账号”；API 输入 endpoint 与密钥，无安装步骤。
高级运行参数在服务详情的高级区域，不能占据首次接入的主要阅读路径。

详情保留服务身份、当前阻断原因、下一步与已完成步骤。配置、授权挑战、
模型与分配属于同一对象；离开再返回恢复该对象，而不是重新开始。
已配置对象可直接进入要修改的步骤，不强制重复整个向导。

Desktop 全局 Settings → AI 使用“我的模型”，移除 Provider 管理导航。
显示本人可使用的模型、来源归属、可用状态和个人默认值。
既有个人接入策略开启时，另提供“连接我的账号”，只允许本人连接和断开。
策略关闭时不出现可点击的个人接入入口。管理员管理入口只对有管理权限的
账号可见；普通用户不会被要求替共享服务登录。

## LC-02 接入与连接

共享路径：
选择供应商 → 必要时安装 → 连接账号 → 检查连接 → 确认模型 → 验证调用
→ 分配用户 → 用户 Desktop 可见 → 用户发起对话。

安装成功即在原位置显示“已安装，尚未连接”，主动作变为“连接账号”。
重装/升级会使受安装版本影响的证明失效；不能延用旧适配能力声明。

API 保存密钥只表示“已保存，待检查”；只有鉴权检查成功才是“已连接”。
CLI 登录挑战采用本目录已有的 Owner、attempt、deadline 与回传合同。
授权页面在操作者自己的浏览器打开，不尝试打开远程 Station 主机浏览器。
弹窗被阻止仍保留链接。设备码与回传码只在授权区展示；失败、取消、
过期、重启中断均保留服务上下文和明确的恢复动作。

连接检查只证明当前绑定的账号。模型页显示目录依据：“厂商返回的模型”
或“由 adapter 选择模型”。不能把 Default/Auto 伪装成确定的厂商模型名。
不支持枚举的 adapter 可以验证其默认选择，但不能凭空生成多个型号。

## LC-03 验证、分配和真正可用

验证请求绑定 Owner、服务实例、凭据 generation、配置版本、adapter 版本
和模型选择。页面显示被验证的模型、结果、时间与失效原因。
一次成功只证明该次调用；不承诺账号之后始终有额度或厂商永不故障。

验证使用该服务正式执行路径的受限无工具短请求，不能用另一个独立探测
脚本证明业务执行路径。可能发生厂商用量，触发前说明。

分配以模型为粒度选择真实用户或既有用户组，显式提交。
可以保存待验证的配置，但未验证模型不能发布为“可用”。
撤销一个人的权限不会销毁其他人的连接；不会注销共享账号。

可用条件：服务启用、当前连接有效、当前版本模型证明有效、用户 grant
有效、账号策略允许。调度时重新检查这些条件；缓存和 UI 选择不授予权限。
“已分配”与“当前可调用”分别表达。厂商拒绝、额度不足或中断后就地恢复，
不能继续使用过期证明，也不能用同名个人配置进行隐式 fallback。

首次完成后显示“已向 Alice 分配 1 个模型”及“按 Alice 权限试用”。
管理员试用不代表 Alice 的真实消费链已经通过；验收必须用 Alice 的
正式 Desktop 会话实际发送并收到回答。

## LC-04 消费、默认和失败

默认值属于本人。只供新会话选择，不能修改运行中会话的模型。
默认模型被撤权或连接过期时保留偏好但标记不可用，暂停发送并要求显式
选择；不静默切换到另一家可能计费的模型。

共享账号过期：消费者看见“共享模型暂不可用，管理员需要重新连接”。
个人账号过期：本人可直接重新连接。断网：保留模型与草稿，显示连接状态。
调用超时/额度不足：保留输入，允许在原会话重试或主动换模型。
撤权：立即从可选目录排除，服务端拒绝旧选择的后续发送。
已完成对话历史不被删除；运行中调用按既有取消和授权失效合同处理。

个人路径采用同一生命周期和同一验证规则，Owner 固定为本人，不出现用户
分配步骤。普通界面不接收协议、argv、环境、目录等控制面参数。
底层二进制可在节点共享；账号材料、配置和执行证明不跨 Owner 共享。
个人连接策略不授予节点安装权限；服务未准备时，由管理员准备后本人再连接。

## LC-05 页面稳定与错误合同

本机 capability session 重试由本机能力 Owner 管理；不以此重载模型目录、
默认值或管理员服务目录。模型可在没有本机工具能力时使用 Station 执行。
Session/Station/账号切换是完整失效，真正的模型/grant 更新是定向失效。

目录、默认值、Agent 列表使用独立请求状态和 source identity；
首次未知状态可用固定几何骨架，已建立的空态或内容不能被后台 loading
替换。刷新、失败与过期在保留的内容区更新状态。请求去重并 fencing：
旧账号/旧 Station 请求不能覆盖当前快照，离开页面不清除未提交输入。

非成功 HTTP 响应由已有 Station 错误解码器处理；Protobuf 不转成 UTF-8
展示。未知错误只给稳定业务文案和追踪标识，不暴露二进制、路径与凭据。

## LC-06 交互线框和证明

线框复用现有 Prototype Portal、唯一 Desktop Shell 和 Station Dashboard。
两端消费一个带 Owner 的模拟图；安装、连接、模型证明、grant 和个人默认
在切换站点或刷新后保持。授权与模型调用均明确标为模拟，不接真实账号。
消费者不出现管理入口，不把体验模拟当生产验收。

当前只交付 drafting 线框，未进入 high fidelity，也不声明 Experience
独立评审、admission 或正式原型确认已通过。
UI 使用已有 token/组件；signature 是“当前缺口直接成为下一步动作”。
主对象是一个模型服务；内容、操作、授权浮层与恢复状态由该对象拥有。

需要覆盖：首次空态；CLI 安装后继续；授权成功/取消/失败/过期；
API 保存后检查；目录空/失败；模型验证失败/重试；模型级分配/撤权；
两用户隔离；默认失效；消费者实际对话；断网与恢复；页面刷新/草稿保留。
线框成功仅为交互候选证据。厂商真实授权、真实调用、重启与凭据生命周期、
暗色、国际化扩展、辅助技术和原生 E2E 分别记录未证明范围。

## 收敛与验收

批准后由原 Owner 落地，不新建第二套安装、凭据、目录、grant 或默认服务。
生产清理包括 Desktop Provider 页面与相关导航；Dashboard 孤立安装入口；
Provider 默认值与个人默认值混淆；共享 loading 和跨域全图重载。
同一改动更新本目录与现有 control-plane/runtime 文档，不能留下两套规则。

完成条件是完整产品 Journey：管理员新接入 → 真实供应商授权 → 模型实际
调用验证 → 分配 Alice → Alice Desktop 选择/发送/收到回答 → Bob 拒绝 →
撤权/过期/重连/断开 → 旧凭据无法再调度 → 测试数据与进程清理。
任何缺少真实供应商或正式消费路径证据的单元保持 UNPROVEN。
