# CLI 账号连接：产品合同草案

状态：draft。产品目标由本文件定义；实现关系见 design.md。

产品承诺：用户从当前服务商直接开始登录，完成供应商授权后回到同一服务商，
看到连接结果并能使用其授权模型；失败时在原位置恢复。

共享服务商由 Dashboard 管理员连接。个人服务商在既有个人策略开启时由本人
连接。普通共享服务商消费者不拥有该资源的供应商账号，不得被引导去替管理员
登录；其恢复提示必须明确由管理员重新连接。本人可连接的服务商只呈现
“登录 X”“重新连接”“断开连接”，不暴露 CLI 命令、环境变量、目录和回调端口。

能力：

- PCA-C01：按实际安装版本声明登录方式，提供直接“登录 X”入口，required。
- PCA-C02：在同一流程展示授权链接、设备码或回传码输入，required。
- PCA-C03：登录后自动检查鉴权、刷新模型，并独立显示调用检查结果，required。
- PCA-C04：取消、超时、重新登录和断开连接均能在原位置完成，required。
- PCA-C05：API key 方式提供精确“获取密钥”链接与当前页保存操作，optional-advertised。
- PCA-C06：不支持的登录方式在开始前明确说明，不能出现必然失败的按钮，required。

PCA-J01 首次连接：选中服务商 → 登录 → 打开供应商授权页 → 在供应商页面授权
→ 如需要，在本页输入回传码 → 本页自动显示登录检查 → 刷新模型 → 可选测试调用。
按钮启动失败必须保留“打开授权页面”链接；禁止只尝试远程主机浏览器。

PCA-J02 重新连接：回到同一服务商 → 重新连接 → 成功后替换旧登录。
失败或取消保留仍有效的旧登录，并显示旧连接是否可用。

PCA-J03 断开连接：说明会使依赖该登录的后续调用不可用 → 确认 → 移除登录 →
可见未连接状态；之后不能用旧缓存继续调用。

PCA-J04 密钥连接：获取密钥 → 供应商精确管理页 → 回到原服务商输入密钥 →
保存 → 检查。保存成功和有效鉴权必须分别表达。

支持入口为 Dashboard 浏览器和策略允许的 Native Desktop 个人服务商页面。
移动端不复制终端操作；若提供相同浏览器管理页面，可执行同一授权链路。
本轮不新增安装体系、任意远程终端、Applet、供应商密码代填或宿主登录继承。
