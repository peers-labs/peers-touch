# CLI 账号连接：决策草案

所有决策状态为 proposed，未修改既有 active 合同。

PCA-D01：保留共享资源由 Dashboard 管理、个人资源由本人管理。
用户不因登录而获得共享配置或安装权限。替代项“任意普通用户替共享资源登录”
会改变共享凭据 Owner，拒绝。代价：普通共享消费者的重新登录需要管理员动作；
其页面必须明确该恢复责任，不能给出不可执行的终端提示。

PCA-D02：适配厂商原生登录流程。Cursor 浏览器挑战、TRAE 内部版 SSO 设备授权、
Codex 设备授权、Claude 浏览器及回传码分别适配。
替代项“所有 CLI 都填 key”无法覆盖 TRAE 或账号订阅；“仅给官网链接”不能把
浏览器授权绑定到 Station 进程，拒绝。代价：需要版本能力验证和厂商升级回归。

PCA-D03：登录材料绑定现有 Provider Owner，复用加密 Envelope；
执行私有目录只获得该资源批准的凭据投影。替代项共享 HOME 会泄漏历史、
settings 与缓存，拒绝。代价：需要验证供应商凭据文件/keyring 格式和刷新写回，
未知存储方式保持 unsupported。

PCA-D04：不修改厂商 redirect URI。设备方式优先；厂商回传码通过本页提交；
无法适配的 localhost 自动回退被明确拦截，提供已验证的 key 方式。
替代项让用户自行 SSH 转发、复制服务器 auth 文件不符合直接入口目标。

PCA-D05：不透明的 CLI 刷新路径采取凭据绑定的独占 lane，
直到 adapter 能证明安全并发刷新；等待有界、可取消且不得阻塞管理 UI。
代价是该 Owner 的账号登录调用并发受限。后续可在真实刷新并发证明后解除，
不能通过乐观复制 refresh token 宣称并发安全。

PCA-D06：安装、鉴权、调用结果独立。登录完成须状态检查，模型调用须单独真实
请求。失败不会被改标为“就绪”；恢复动作由资源 Owner 与失败类别共同决定。
