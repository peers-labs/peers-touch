# 持续任务能力 — 状态模型

状态：accepted（Owner 2026-11-02 确认）。TW-20261101。描述用户可见语义；数据库与协议表达以 data-model.md 与 Model proto 为准。

## 三个不同生命周期

任务沿已有 Conversation/Topic Owner 保存目标、资料、成果与接收关系，能在未运行时继续存在。用户可见层中，一个任务承接一条连续对话；草稿、附件、引用和执行上下文按任务保存。同一目标的追问与复测继续该任务，独立目标才新建任务，不要求用户创建或切换会话。执行可为草拟、进行中、待介入、阻塞、待验证、完成或取消；这些是运行事实，不是列表分类。列表组织由用户自定义标签负责，无独立归档状态或归档 Tab。

Turn 为排队、已接受、运行、等待回答/审批、部分结果、结束、失败、取消、未知副作用。排队回执仅表示队列接受输入，不是执行端接受本轮；执行 admission 再核对当前授权、角色与版本。结束不等于任务验证通过。任何控制决定必须关联原 Turn/request，过时请求只能回看。

工作面为准备读取、读取中、可读、损坏、不支持、无权限、来源失效；绑定当前资源和版本。打开工具/reader 不更改执行状态。正文加载失败保留原对象、版本选择、草稿和已读结果。

人工修订产生新成果版本，不覆盖历史；旧检查与接受不应用于新版本。派生网页引用其正文版本，正文改变后旧网页标记过时；用户显式更新预览后产生新网页，来源绑定当前正文。数据计算、文件读取和版本比较的原型结果是真实本机字节；不等于模型判断、外部系统执行或正式验收。

## 状态转移与恢复

首次进入→空任务 composer；发送前检查资料、环境和授权；接受后才清空已发送槽并建立本轮。前置失败保留原 draft/attachment，解释缺失和恢复入口。排队是独立接受结果，执行时再核对当前授权。

运行→waiting request：显示真实范围及允许动作；回答/批准需当前 request 有效。拒绝/取消回读未执行或已经发生的副作用。断连→最后确认状态；不把本地 cancel 点击直接显示为服务端已停。

执行→部分结果/待验证：产物可以阅读，任务未完成。检查→失败保留版本和修改上下文；修订→新版本→针对新版本复测。检查通过后由任务生命周期 Owner 按产品定义中的当前接收条件决定待用户确认或完成，不采信 Agent 自报完成。结果、目标/条件、来源、环境或检查合同变更令相关依据 stale；回读只能看到旧依据及失效原因，不续用旧 PASS。

未知副作用→核对真实执行状态→已执行/未执行/仍未知；只有核对后才允许有外部写入的 retry。恢复动作返回原任务/输入位置，不把失败导向无关 Profile。

## 控制、队列与授权的决定

Stop 默认作用于当前 Turn，并暂停本任务后续队列。队列内容保留，用户回读停止/副作用结果后，显式选择继续队列或取消选中项；不会在 Stop 后自动 admission 下一轮。“停止并取消队列”是另一明确操作，逐项回读取消结果。请求已发送未获回执时显示“停止请求中”，不能提前显示已停止。

排队输入可在 admission 前修改或取消，修改产生新队列版本；admission 竞争时以执行端回读为准，已开始的项目改走当前轮控制。失败、未知结果、待介入或授权失效暂停后续 admission；成功终止才按顺序开始下一项。队列不自动重放未知副作用。

标签保存在同一任务对象，空值忽略、同名去重；标签名不保留运行语义。例如标签叫“进行中”也不启动任务或解除暂停。添加、改值或移除只改变列表组织，取消编辑不写入；最后一个标签移除后任务仍在全部任务中。保存历史中的旧归档标记在读入时保留为可编辑标签，后续模型只保存标签。永久删除活动任务或批量任务先核对每项活动、队列和独占资源：停止确认并清理独占资源后删除历史，共享资料仅解除引用；任一项未知则不删除该项，并保留逐项失败结果。范围不能在提交后扩大。

审批批准只授权所展示的动作、参数、资源和有效 request；执行时仍核验权限，批准回执不等于工具完成。拒绝阻止尚未执行的动作并使本轮待用户选择替代路径；不会默认执行弱化版本。澄清回答只释放对应 request，取消澄清保持本轮等待或显式停止，不释放其他轮次。

移除来源使未来 Turn 不再采用。服务端撤权回执后禁止新读、admission、resume 和后续工具步骤，客户端关闭敏感阅读并清理无权缓存/草稿引用；活动轮请求停止，已发送到执行器的输入和已发生的副作用不能宣称追回。结果在回读前重新授权，迟到输出不能重新显示被撤销内容。恢复授权后先核对最后执行状态，再由用户显式继续，不重放旧审批或未知写入。

## 规则、记忆与来源

Profile 保存产生新规则版本，后续 Turn 消费，已运行 Turn 保留原快照。能力绑定与执行授权是不同状态；enabled 不等于可用。

能力审批策略变更由原 binding Owner 保存版本，后续请求采用当前策略；现存 pending 不因改为 AUTO 而被自动批准。收紧或撤权在实际消费时阻断，不能让旧规则快照越过当前权限。

Memory 状态为候选、确认、拒绝、修订、冻结、删除、来源失效；范围与来源可解释。新轮仅消费当前有效授权版本；删除/纠错不能只删一行 UI。历史 provenance 与当前可读内容分开，撤权后不得暴露敏感正文。

资料选择→实际读取→授权来源→被采用。附件名称出现不是被采用；上下文来源投影仅记录执行实际消费的版本。移除影响未来 Turn，不能宣称已经生成的字节被逆转。

当前原型沿同一任务 Owner 保存有效资料集合。相同文件名的新字节更新当前版本，旧字节保留在原消息；更新或重新选择资料明确其采用顺序。同字段的新资料优先，未被覆盖的其他字段仍保留。文件工作面可排除/恢复某份资料，操作只影响后续轮次；发送时冻结资料修订号，旧结果的检查不能续用于已改变的资料范围。此处的字段合并是有界原型变换，不代表任意自然语言推理或事实验证。

## 多端、删除与视图

远端执行可在另端回读/介入；本机执行依原设备。账号/Station 切换隔离源投影、缓存及 draft，不自动合并。Search 和通知通过重新授权的 opener 回同一生命周期。

停用 Agent 按产品定义阻止新执行并回读活动停止，历史独立保留；恢复角色只恢复可用性，旧轮、队列和审批不自动重启。永久移除角色配置不能隐式删历史，历史保留安全角色来源；删除历史另走上述任务删除。task-workbench交互线框原位模拟停用并保留threads；普通基线的角色删除行为仍不能作为本候选落地依据，永久移除与批量清理尚未模拟证明。

窄窗口切换列表/会话/工作面不生成新任务，不清 draft；返回恢复焦点和版本。无变化后台同步不改变这些视图状态。

正文编辑草稿属于任务中的确切成果版本，按 artifact ID 保存内容、基础版本及更新时间；切任务、切工作面、Profile 返回和刷新不清除。显式放弃只删除该草稿，保存产生新版本并保留旧结果。任务笔记、尚未提交的笔记输入及当前工作面选择也属于任务，不以组件存活代替保存。当前原型使用同一 Thread 的 workspace 投影持久化，不另建工作面 store。

成果接受按 artifact ID 保存检查快照和时间；有效性要求版本、字节、目标、条件和资料修订一致。各文件当前版本全部有效接受才显示“成果已接受”，不推出 Task done。新成果无接受，旧接受记录保留；上下文变化不删除历史，也不能由重新检查自动续用旧接受。派生任务重新分配消息、成果、会话、资料 ID 并重绑内部引用；保存的笔记继承，队列、输入草稿、检查与接受不继承。

## 当前候选的执行投影

同一 Thread 保存目标、目标/条件变更历史、当前轮推进记录及来源修订。计划步骤只反映本机有界变换：资料读取、成果写入、等待核验和人工接受，不代表真实模型规划。修改目标保留旧计划快照；新的轮次使用当前目标。结构/内容检查同时绑定结果字节、版本、目标、条件和资料修订，任一变更不能续用旧接受。

活动轮按任务做同步 admission 去重，消息 phase 是可见执行投影，计时器按任务归属。成功、失败、审批拒绝和停止分别释放对应活动轮；停止取消该任务计时器并暂停队列，不清其他任务。刷新将未确认活动转为 interrupted，暂停所有自动队列，不重放旧批准。

后台成功轮可继续所属任务的队列；准入重新核对所属角色及模型目录。入队项在准入前保留正文、附件、会话和引用，修改/取消只影响该项。后台准入失败的说明保存在所属任务，不能覆盖另一任务的输入提示。恢复队列是明确动作，不把另一任务完成作为当前视图切换理由。

正文和网页反馈在原用户消息及新成果上保留来源 ID、版本和引用。HTML DOM 选区只有已渲染页面的文字与版本绑定，没有持久节点锚点。旁聊保存引用快照，采纳记录表示已带入主草稿，不能表示已执行。存在未保存正文编辑时，新成果不得抢走基础版本或删除草稿。
