# 持续任务能力 — 产品定义

状态：accepted（Owner 2026-11-02 确认；实施由执行计划 TW-20261102 承接）。TW-20261101。现有 Agent 产品的演进，不是新的首页、模块或任务数据库；各项能力的生产完成证据以执行计划 outcome comparison 为准。

## 价值与用户对象

面向反复调查、写作、处理文件和开发软件的个人及协作者。承诺：在现有 Agent 入口，把资料和目标交给一个可复用角色，执行中可以介入，结果可以阅读和修改，验证后重新打开仍可定位。

首次有用结果是一份基于用户资料、能打开并继续修改的交付物。持续价值来自任务目标、过程、资料、角色规则和已确认记忆的延续。排除独立 Project CRUD、恢复 Atelier 入口、未经授权的发送/发布、以临时 CLI 目录冒称持久环境。

用户对象沿已有 Conversation/Topic 与 Turn 演进。任务保留目标、资料、成果与接收关系，并承接一条连续对话；Turn 是这段对话中一次被接受的执行。同一目标的继续交流不要求用户另建会话，也不因改名“Task”另建一套 Owner。Agent 是可复用角色，选中角色是上下文筛选，不是唯一寻找任务的范围。全局 Search 可以跨角色寻找获授权内容。

## 任务边界与接收结果

同一目标的追问、补资料、改稿和复测继续原任务，产生新 Turn。独立目标由用户在现有 composer 明确新建任务，进入新的 Conversation/Topic 关系；不因执行器猜测主题变化自动迁移或拆分历史。任务改名只改寻找名称；修改目标须显式修改接收条件，保留旧条件及已有结果的关系。

同一任务只有一条用户可见的连续对话，追问、补资料、改稿和复测都留在这条对话中；草稿、附件和引用按任务保留。历史审批不自动成为新轮授权。当前轮仍在执行时，后续输入进入该任务的队列或等待本轮结束，不提供“续接新会话”。

任务列表跨角色汇总工作，不在任务下展开会话层级。用户用自定义标签组织任务；全部任务和已有标签共享一个下拉选择，不设置“最近/待处理/执行中/归档”等固定分类 Tab，也不提供独立归档流程。运行、待批准/回答与暂停是执行事实，按需要作安静提示；它们不决定用户分类。标签的添加、修改、移除与查找不改变任务身份、运行、队列、资料或结果。

Agent 与任务列表各自只用一行头部容纳名称/范围、搜索和新建。搜索点击后原位占满该行，暂时隐藏其他头部信息；关闭或 Esc 清空查询、恢复原控件和搜索按钮焦点，列表位置不移动。任务日期随标题并排，标签与确实需要介入的运行提示才使用补充行。首次开始从自然目标与资料进入，示例装载器、强制状态开关与验证口令表不属于产品路径。

旁聊读取用户选定的授权截点，结论只能经显式操作送回主任务草稿。fork 为独立目标分支，用户选择继承的历史、资料和结果版本；不继承待批请求、活动进程、写权限或原任务的完成证明。能否独立写资源先检查环境，不能借复制会话获得原资源授权。实体、存储与分支绑定由 Architecture 沿已有 Owner 定义。

每个任务在执行前明确所需接收结果和判定办法。资料任务可要求用户阅读后确认内容满足目标；代码任务必须包含所声明检查的真实结果。Agent 可提出验收条件、生成候选交付和解释检查，不能用自己的“已完成”回复批准自己的交付。真实检查回执只证明相应检查；用户确认只证明人工接受，不替代必须执行的检查。

完成由既有任务生命周期 Owner 根据当前接收条件、获授权的结果版本、必需检查及用户确认决定。必需检查未跑、失败、过时或结果不可回读，保持待验证/阻塞；用户可以取消或接受已说明的部分结果，但不能把未验证任务标记为全部完成。目标、结果版本、来源、环境或检查合同变化，相关证明失效；条件变更不能事后静默删掉失败检查。自动完成仅限已明确采用机器判定、必需结果均有当前依据的任务。

停用角色禁止新 Turn 和续执行；现有运行发出停止请求，队列暂停，待批请求失效，实际停止结果回读后显示。历史保留并按当前权限阅读。继续旧任务须由用户选定另一个可用角色，核对权限及采用的规则后显式开始新 Turn，保留原轮来源；停用不是自动换角色。永久删除历史是独立操作，不能在删除 roster 时级联清空用户资料。

## 入口与复用约束

全局入口保持 Search / Chat / Agent / Moments 和全局 Settings。Agent 内只保留 roster、任务列表、当前任务对话和当前工作面；无第二个“Agent”页签，无 Home/Workbench 同级菜单。

当前原型直接复用Shell→AgentChatPage→AgentProfile、shared/prototypeAgentModels、SearchOverlay。生产已建成的AgentWorkbench→AgentRail/TopicRail/ConversationRail、chat store、Portal、既有消息/附件/Markdown阅读组件、Station Memory和Search runtime是演进基础。当前生产树的client-chat-core是缓存底座，不能当作已存在的完整文件viewer。复用责任、数据和消费者关系，不把原型错误处理器复制到生产。

设计候选中的 AgentTaskWorkspace 是已有 AgentChatPage 的视图消费者。任务、连续对话、Turn、队列、成果版本及记忆均由原 Owner 持有；视图只持有面板、选择与阅读状态。文件阅读、正文修订、网页预览与差异比较引用同一任务成果，人工修订保存为新版本。派生网页保留正文来源版本；正文更新后旧预览须显示过时并提供重新生成入口。

Agent 行的“⋯”仅提供 Agent Profile 管理入口，能力和记忆通过 Profile 内部 section 切换；菜单及列表底部不重复注入能力和 Memory 导航。Profile 身份与 SOUL/AGENTS 保留独立编辑，绑定沿 extensions；Memory 在 Profile 统一管理，CRUD、召回、纠错和删除沿原 Memory Owner。工作面只展示上下文采用关系并回到 Profile 管理。Dashboard 负责模型配置、安装、连接和用户授权；Desktop 保留个人默认/会话覆盖和明确恢复入口。工作面沿原 Portal 和共享 reader 扩展。

## 能力范围

18 个维度保持完整，细分操作及缺口见逐功能审查。Required 不因当前原型缺失而降级为 deferred。

- **C01 required 入口与寻找**：现有 Agent/全局 Search→获授权会话/消息/版本→真实 opener 定位。列表用全部任务、自定义标签和原位展开搜索寻找，不新增一级页面。
- **C02 required 持续任务管理**：创建、继续、改名、置顶、标签增改移除；切换与重开保留目标、草稿、结果和位置；标签不控制执行，角色停用不隐式删除历史。
- **C03 required 运行控制**：排队、取消、审批、澄清、过时请求；steer 仅在环境支持时广告，不支持则保留下一轮输入。每次控制有对应 Turn 回执。
- **C04 required 环境与资料**：启动前明确执行位置与可用能力；授权资料的字节被实际消费，断连后先回读。临时模型调用与持久 Agent 环境分开说明。
- **C05 required 文件与产物**：实际字节、不可变版本、来源和授权；共享多格式 reader；引用/HTML 批注→同一草稿→新版本；错误和外部打开降级清楚。
- **C06 optional-advertised Browser Use**：有能力才提供启动；真实操作/读回、任务归属、人工接管租约和账号隔离闭合。
- **C07 deferred Computer Use**：缺 Native 权限与执行证据前不广告。
- **C08 optional-advertised Terminal**：真实进程输出、退出码、stdin、停止和保留；断连不能伪装运行，结果回流文件/验证。
- **C09 optional-advertised Diff**：真实前后版本、冲突、反馈再改、回滚影响；提交/发布分别授权。
- **C10 required 计划与验证**：计划和检查来自实际执行；生成、退出、通过验证分别显示；验证绑定交付版本，缺证据不完成。
- **C11 required 上下文与来源**：采用的附件、Knowledge、规则、Skills、Memory 可回看；移除/撤权改变未来消费，历史可见性受权限约束。
- **C12 required Memory 质量**：提取候选、确认/拒绝、范围、来源、改写召回、纠错/删除/失效停止消费；不把临时任务指令提升为全局偏好。
- **C13 required Profile**：身份、SOUL/AGENTS、能力与实际可用性、角色范围记忆；新轮读新版本、当前轮保留快照。
- **C14 required 能力与授权**：Dashboard 安装/连接/分配→Desktop 选择→真实回答/工具结果；撤权、过期、重连和返回当前任务。
- **C15 degraded 多端**：远端任务在获授权设备可读/介入；本机执行依原设备在线，其他端只读同步记录和明确状态。
- **C16 deferred 自动化/多 Agent**：本次单任务交付不依赖编排，无空的自动化启动入口。
- **C17 degraded 分享**：授权内打开/导出指定版本；公开分享另立范围。
- **C18 required 恢复、隐私与可信完成**：区分失败、未知结果、取消、部分完成；不泄漏凭据/原始提示/敏感路径；无变化同步不重初始化。

## 平台与完成判定

Desktop 复用连续栏，窄窗口任务列表→会话→全屏工作面，返回保留位置。Mobile 同一语义适配触摸，不承诺手机本地 shell/worktree；Browser 的本机能力依明确桥接，没有桥接在接受操作前说明。跨端同步的是获授权投影，不是任意文件、Cookie 或进程。

完成要求：一条资料任务和一条被广告的代码环境任务，都通过输入→实际消费→介入→阅读→反馈→新版本→验证→重开的链；Memory 必须在第二任务被正确召回，纠错与删除后停止旧消费。当前只是候选合同；完整高保真、独立 EDX 评审及生产证明尚未成立。

业务操作和接收方断言唯一展开在 [验收矩阵](./acceptance-matrix.md)。18 个能力、10 条 Journey 与既有52个审查组是覆盖索引，不是52次独立成功，也不替代逐操作判定。当前评审显式使用功能闭环合同；active AC-PRODUCT-01 的既有要求保留，本包语义在 Owner 2026-11-02 确认后成为产品准则，正式 Acceptance 准则另由验收计划管理。
