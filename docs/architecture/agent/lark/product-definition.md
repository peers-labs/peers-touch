# 飞书助手 — 产品定义

> **Status**: draft
> **Version**: v1.3
> **Created / Updated**: 2026-10-18
> **Owner**: Agent / Channel

## 产品承诺

先把一个飞书应用身份连接到 Peers，再按需决定由哪个 Agent 响应消息。
“创建托管应用”和“使用已有应用”只是取得应用身份的两种方式，完成后都生成
同一种 Lark Connection；私聊、群聊、话题、图片和文件是连接后的自然消息场景。

产品面向个人使用者。默认路径先呈现连接名单，再进入一个连接的连续工作面。
系统在后台完成应用身份和消息能力连接。默认响应 Agent 是连接后的独立配置，
会话 Agent 是更下游的路由覆盖。用户可建立多个互相独立的 Lark 连接；
高级能力只在用户表达对应意图或某个连接需要恢复时出现。

## 控件必要性

界面只允许三类控件：

1. 用户必须做出真实选择，例如切换默认响应 Agent、为某个会话指定其他 Agent。
2. 用户主动要求额外结果，例如创建自动化、授权自己的文档或日历。
3. 系统无法代替用户完成恢复，例如重新授权、修复连接或断开连接。

协议、scope、WebSocket、事件订阅、路由规则和权限组合由系统推导与校验，
不得作为默认操作暴露给用户。仅展示技术字段不会构成高级能力。

## 用户能力

- **立即开通**：点击 Add Lark 后打开全新空白 Dialog。用户可扫码创建托管应用，
  或输入已有应用凭据；两条路径都先建立身份和消息能力，不要求选择 Agent。
- **多个连接**：新增连接只追加对象，不覆盖现有连接；每个连接独立保存可选默认响应 Agent、应用身份、
  会话偏好、自动化、个人授权、测试投递和活动记录。
- **名单管理**：连接可设为默认、暂停、恢复、打开详情或删除；删除默认连接时，
  系统把默认身份转交给下一个可用连接。
- **自然使用**：在任意私聊、群聊、话题、图片或文件上下文中直接交流；仅在平台限制或能力不支持时解释原因。
- **默认响应 Agent**：连接建立后可选；配置或切换时不重建 Lark 身份。
- **会话偏好**：用户需要时，可让指定会话由另一个 Agent 处理。
- **自动化**：用户用“何时发生什么、希望得到什么”表达需求；系统负责事件和投递实现。
- **我的飞书**：仅在 Agent 需要个人文档、日历或联系人时按需授权；Bot 身份与个人身份分离。
- **已有应用**：已有 Lark App 可用于创建新连接，也可替换某个连接背后的应用；
  系统统一检查并给出一个修复动作。
- **健康与恢复**：健康检查覆盖身份、消息和 Agent 全链路；故障保留连接和用户设置。
- **暂停与删除**：暂停可逆且保留全部连接数据；删除不可逆地移除该连接配置，
  但不删除 Agent 或 Lark 中已有的对话内容。

## 高级能力完成定义

高级能力不能以计数器、布尔开关或一次性成功提示代替真实结果。每项能力必须形成：

`进入 → 草稿 → 校验/预览 → 保存对象 → 查看结果 → 编辑/暂停/撤销 → 失败恢复`

- 会话偏好保存会话、Agent 和启停状态，支持编辑、暂停、恢复与删除。
- 自动化保存触发条件、动作、执行 Agent、接收方和最近投递结果，
  支持试运行、编辑、暂停、恢复与删除。
- 个人 Lark 显示授权中的状态和已连接身份，支持过期恢复与确认撤权。
- 已有应用先校验凭据与能力，再修复缺失项，最后由用户确认创建连接或替换当前应用。
- 测试消息显示接收人、发送中、已送达或失败结果，失败只重试投递。

会话偏好和自动化草稿在退出聚焦页面和刷新后保留。新增连接表单是一次性会话，
每次打开、关闭或成功后都清空，不恢复上一次输入。App Secret 不进入客户端持久化；
提交后由 Station 使用稳定 KEK 的信封加密存储，重启后仍可按用途解密使用，
明文不会返回客户端。连接间的草稿、授权、路由、自动化和投递状态不得串写。

## 信任承诺

Bot 身份、请求人身份与模型凭据分别授权。群成员不会借用连接者的个人账号。
有副作用的动作在用户可读预览后执行；撤权会关闭尚未执行的动作。
私有推理、明文凭据和底层连接细节不出现在消息、列表或诊断导出中。

## 完成边界

Desktop 与桌面浏览器共用全局 `Settings → Channels → Lark` 入口。
Bots 与 Lark 是 Channels 下的同级入口；Message Publishing 是复用框架，
不是用户可见的父级。

生产实现仍需用真实账户验证扫码、OAuth、消息与媒体、群上下文、自动化、
权限恢复和结果投递。当前原型只证明交互模型，不创建应用、不取得 token、
不执行 Lark 工具。原型已覆盖多连接交互模型；生产多连接、国际版和 Mobile
仍为未证明范围。
