# 0.0.1 恢复缺陷修复契约

用户授权：修复五项 P1 并重新验证跨端恢复场景。验证范围为定向回归与
Desktop/iOS 原生恢复冒烟，不执行全量 Acceptance，不据此认证完整发布。

- Mobile Access 原生拒绝保留 `code/message/details`，失效 Session 只清理并重试一次；
  网络、权限和身份不匹配不得被当成失效 Session。
- Mobile 路线所有者从原来的可信发现输入续订过期证明，固定 Station、节点、路线、
  generation、relay 与 endpoint。续订不得回退授权 epoch，不改变路线 revision；
  并发切换必须使旧续订失效。
- Federation 唯一事务提交器串行协调账本头、事件和成员投影。已提交的同序号同哈希
  事件幂等成功，不同哈希仍拒绝；退出导入与同步交错后仍可合法重入。
- Desktop 在聊天数据库外安全保存设备签名材料。恢复必须复用已登记设备的签名身份，
  在数据库替换前验证 Station enrollment；材料缺失或登记失败保留原数据库。
- 发布实操证据绑定真实 Journey、平台、步骤、UI/接收端观察与不可变 trace 片段，
  截图属于该片段。完整报告逐项验证九条 Journey × 两个平台，拒绝空集合、
  错误平台与没有片段映射的共享证据。

回归证据须来自修复后源码。原生冒烟覆盖恢复后双方收发、过期路线返回、
失效 Session 恢复，以及 Federation 退出/同步/重入。无法运行或缺少原生
接收端证据的项目保持 `UNPROVEN`，开发资源在验证结束后释放。
