## 实操输入

`PT_RELEASE_OPERATION_REVIEW_INPUT` 指向仓库外 JSON。输入必须绑定当前干净
源码，并覆盖 Plan 声明的 9 条 Journey 在 `desktop-macos` 与
`ios-simulator` 两个平台上的 18 个实操单元。每个单元必须包含：

- 任务目标、步骤、完成状态、总耗时和等待点；
- 可发现性、操作反馈和恢复路径；
- 分离的测量事实、直接观察和评审判断；
- 当前源码 Evidence Store 中可解析的截图与操作轨迹引用；每项引用同时携带
  对应的不可变 `runManifest` 引用，不依赖可变 latest 指针；
- `traceSegmentId` 指向 `release-operation-interaction-trace` 的唯一片段。
  片段包含相同 `journeyId/platform/steps`、原生 `runtimeCell` 和截图 ArtifactRef；
  每一步具有带 `stepIndex/status/observation` 的 `ui-action` 或断言记录，
  完成结果具有 `ui-visible` 断言。聊天、附件恢复与 Moments 还须具有
  `receiver-visible` 断言。共享轨迹只能通过显式片段映射复用，截图必须属于
  对应片段；错误平台、步骤、截图、空片段或缺少接收端观察均拒绝；
- 按发布缺陷、下阶段 UX、保留的好设计分类的结论；
- 对简单、好用、丝滑、易理解、互联网应用标准与审美五个维度的理由。

缺少实操单元、使用历史源码、只提供截图/Harness/API 观察、包含敏感信息，
或存在未关闭的发布缺陷时，Gate 必须保持 `PARTIAL/UNPROVEN`。
最终聚合逐项重新验证报告中的十八个单元及其不可变轨迹，不能以
`journeyCount` 数值替代实操集合。

## 运行产物

R001-07 生成以下不可变角色：

- `release-operation-review-input`
- `release-operation-analysis-report`
- `release-operation-analysis-markdown`
- `release-operation-analysis-html`

R001-08 只接受同一 Acceptance aggregate 已执行的 completion Gate manifest，
不回退到历史 latest 结果，并生成：

- `release-mobile-ios-desktop-final-report`
- `release-mobile-ios-desktop-final-markdown`
- `release-mobile-ios-desktop-final-html`

最终报告首页必须给出 `可发布`、`有条件可发布` 或 `不可发布`。当前实现仅在
全部必需 Gate 同源码 `DONE/PROVEN`、原生产品证据完整、运行 cell 正确、清理
完成且实操报告无发布阻塞时给出 `可发布`；其余情况 fail closed 为
`不可发布`。
