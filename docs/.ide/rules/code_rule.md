# 代码生成规则

## 通用规则

1. 英语作为代码注释的第一语言！
2. 代码要错落有致，适当的使用注释、空行等，提高可读性。
3. 每次修改，都要记录在注释中，包括修改的原因、修改的内容、修改的影响等。

## Feature 迭代

1. 生成前，要和用户确认业务逻辑架构、目录架构
2. Desktop 优先使用 LobeUI 的组件库，没有时再问用户是否要使用 antd
3. 每个类、方法实现等，都要检查是与否当前业务实现的的逻辑、架构、可读性达到一脉相承的地步
4. subserver 的代码组织，必须符合 DDD 架构，包括聚合根、领域服务、领域事件等。
5. 域内应用通信必须是 protobuf 协议，非必要不能用 JSON 协议。

## 修复规则

**重要**：你必须记住，以下仅在我让你修复问题是生效

1. 永远不准打补丁式修复bug，必须通过架构视角来定位、审视当下实现的根因。不准遗留无用代码！
2. 永远不要自己静默修复，找到根因后，要告诉我，给我方案，我审核了才能实施。

## 提交规则

1. 该 ignore 的不要遗漏
2. 检查是否带有密钥在代码、配置文件里，绝对不允许带入
