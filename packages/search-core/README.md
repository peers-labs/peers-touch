# Portable Search core

Canonical wire: `model/domain/search/search.proto`, generated by `build.rs`.

- `ports.rs`: object-safe `SearchContributor` (`query / hydrate / resolve`),
  trusted execution context, cooperative operation cancellation.
- `contributor.rs`: declaration, candidate and batch-reply conformance.
- `cache.rs`: bounded memory payloads, shared reads, subscriber detachment,
  monotonic expiry and active operation fences independent from LRU eviction.
- `runtime.rs`: query/hydrate/resolve coordination over a trusted host binding
  and native executor; validates source replies before caching them.
- `session.rs`: shared multi-source query sessions, rank snapshots, issued
  reference associations and serialized continuation advancement.
- `projected.rs`: domain-neutral reader adapter, observed read state, and
  original-owner last-scanned continuation.
- `remote.rs`: trusted remote port adapter (integrator-owned).
- `requests.rs`: bounded, identity-scoped request admission and cancellation.
- `query.rs / tokenize.rs`: shared CJK/Latin FTS semantics.
- `ranking.rs / cursor/`: fusion and authenticated, expiring continuations.

Hosts implement `SearchExecutor` and `SearchBinding`, execute source futures
and supply original-owner guards. Cache commit
and final publication must be serialized with identity, policy and source
invalidation. A content hit never grants authority. No database, Tauri, HTTP,
UI tree, model provider or Applet runtime is owned here.

## Host API

`B: SearchBinding` is a concrete composition (for example a host's enum), not
`dyn SearchBinding`. Contributors themselves remain object-safe.

```rust
pub fn query_all<B: SearchBinding>(
    &self, bindings: &[B], input: QueryIntent, cancel: &CancelToken,
) -> Result<SearchResponse, SearchError>;

pub fn resolve_all<B: SearchBinding>(
    &self, bindings: &[B], source_id: &str, resource: ResourceRef,
    cancel: &CancelToken,
) -> Result<ResolvedResource, SearchError>;

pub fn read_states<B: SearchBinding>(
    &self, bindings: &[B],
) -> Result<SearchReadState, SearchError>;

fn read_state(&self) -> Result<SourceReadState, SearchError>;

fn read_authority(&self) -> ReadAuthority; // defaults to LocalSnapshot

fn publish_sources<T>(
    &self, sources: &[SourceReadState],
    publish: impl FnOnce() -> Result<T, SearchError>,
) -> Result<T, SearchError>;
```

`read_states` projects the trusted binding vector without constructing adapters
or reading content. `read_state` is called outside owner publication locks. It must report the
trusted source/binding/content revision, read scope, independent policy
revision, readiness, coverage extent and `no_store`. Its default supports the
existing one-source owner-checked scope. Composite hosts override it per
variant and implement `publish_sources`: atomically compare the supplied
vector against the authenticated partition and all relevant original owners,
then execute the closure under that guard. Do not nest per-source guards
which share authentication or Store locks. Unavailable sources must not
prevent publication of another source's authorized items.
An unavailable source returns a `SourceReadState` with `Unavailable`, not an
authentication error; identity transitions still fail the whole operation.

`ReadAuthority::LocalSnapshot` requires exact content/read-scope/policy state
and an original-owner publication guard. `RemoteOwner` binds the owner/source,
native transport generation and exact authenticated actor read scope, with
`no_store = true`. Its pre-read source/policy observations may be empty.
Remote replies must carry actual nonempty owner observations, no-store,
owner-check-required and zero lease. Native transport generations are never
rewritten into remote revisions or grants. Query/hydrate observations update
the response source vector; continuation and resolve compare stable native
auth/transport fields, then re-read the owner. A per-operation PG observation
is not claimed to freeze remote policy or content between operations.

The core uses that guard for session/cache commits and final response
publication, including warm hits. Hosts must also use it around final IPC byte
publication, because returning a Rust value is not the IPC publication boundary.
Adapter construction remains outside Store locks and is rechecked before
registration. `SourcePage.cache.no_store` is ORed into the response source state;
projection fields retain their own read validity. Remote sources without an
original-owner publication guard require a current authority lease or no-store
original-owner read-policy verification on every query/hydrate/resolve operation.
Content validation or a local lock does not authorize Station content.

Existing `query(binding, intent, cancel)` and `resolve(binding, ref, cancel)`
signatures remain one-source reads over the same read coordinator. Direct
query also records issued references. Resolve requires a prior issued
association for this partition, exact source, fusion identity, revision and
full reference. Unknown, changed, expired or evicted associations fail closed.
Before association lookup, the shared descriptor/resource validator rejects
malformed references, undeclared kinds and authority namespaces as protocol
errors. Valid unissued references remain unavailable without calling the owner.
Only that source is called; no kind dispatch, public/private fallback, or
resolver fan-out exists. Hosts still allowlist the returned resolver binding.

## Bounds And Semantics

- At most three trusted sources; generated `kinds/scopes` narrow each query
  before execution. Empty kinds means all eligible kinds; scopes are explicit.
  Suggestions admit Device only. Blank conversation suggestions belong to the
  Messaging adapter, never this core.
- Suggestion eligibility is a static `supports_suggestions()` port capability.
  Unsupported contributors and remote-owner sources are excluded before their
  snapshots enter the query vector. Empty no-store private sources therefore
  cannot poison eligible local suggestion caches or trigger policy networking.
- Each source holds at most 100 unissued candidates. Pages default to 20 and
  reject limits above 100. Fusion uses source ranks, not raw engine scores;
  the original authority/kind/object identity determines deduplication.
- Each source completes query and authorized batch hydration in its own
  pipeline, reusing `runtime::query_source`. Existing pending candidates enter
  that source's hydration directly. All pipelines share the initial five-second
  operation budget; the receiver has an absolute deadline with 100 ms reserved
  for fusion and publication. Slow query or hydration yields source-local
  timeout coverage while completed sources retain their results. Failed source
  windows and continuations are discarded; a new attempt may retry the source.
  Cancelled subscribers detach separately; the last subscriber or deadline
  stops the shared read.
- Hydration precedes cross-source fusion over the bounded candidate windows:
  at most 100 references per source and 300 per operation, potentially more
  than the final 20 rows. Existing valid projection caches reuse content;
  no-store sources reauthorize every window. This trades bounded extra reads
  for source independence. The RRF scores, deterministic tie-break, winning
  source, final page limit and successful-window consumption remain unchanged.
- Session storage is capped at 32 sessions, 640 candidate/issued entries and
  4 MiB. Native read storage, including active reply bytes and key copies, has
  a separate 4 MiB cap: retained native/session content is at most 8 MiB.
  Native displayed response retention is capped at 32 frames and 200 rows.
- Sessions retain references/ranks, not a second result body cache. No-store
  projection reads are never reusable; continuing a no-store source
  rehydrates its unissued candidate window through the original authority.
  Authorized window projections are temporary operation values, never session
  state or a source of resolution grants; only displayed items are issued.
- Cursors are authenticated with an unpredictable runtime-incarnation key.
  They contain only a semantic digest and a session/step reference, not
  query text, object references or native continuation tokens. Source changes,
  first expiry, monotonic expiry or eviction reject continuation, never restart.
  Advancing a session is serialized and committed only after the publication
  fence succeeds. Concurrent subscribers may reuse the same issued page.
- Read scope/policy/lease validity is checked independently of freshness.
  Monotonic retention and issued-reference lease bounds cannot be extended by
  clock rollback. Source failure coverage remains independent; incomplete or
  failed aggregates never become reusable successful empty responses.

## Projected Reader

```rust
pub struct ProjectedPage {
    pub documents: Vec<ScoredDocument>,
    pub next_before: Option<(i64, String, String)>,
}

pub trait ProjectedSearchReader: Send + Sync + 'static {
    fn revision(&self) -> Result<String, SearchError>;
    fn supports_suggestions(&self) -> bool { true }
    fn read_state(&self) -> Result<SourceReadState, SearchError>;
    fn query_documents(
        &self, input: &QueryIntent, ctx: &SearchExecutionContext,
        before: Option<(i64, &str, &str)>, limit: usize,
    ) -> Result<ProjectedPage, SearchError>;
    fn read_resources(
        &self, refs: &[ResourceRef], ctx: &SearchExecutionContext,
    ) -> Result<Vec<ScoredDocument>, SearchError>;
}
```

`ProjectedContributor::new(reader, descriptor, revision, resolver_binding,
cursors)` returns `Result<Self, SearchError>`. The descriptor and resolver are
host configured, never learned from candidates. `revision` fences the original
reader/index binding; `read_state` supplies actual metadata for the just-completed
owner operation. The adapter serializes that operation/state pair and retains
no private projection bodies. No-store comes from the observed state, with zero
lease and an owner check on every read. It is not synthesized from a transport
generation.

The reader owns scan progress `(timestamp, kind, id)`. Empty filtered pages can
still return `next_before`; the adapter signs that exact position and preserves
the first expiry. It never infers exhaustion from document count or truncates
authorized documents independently of the scan cursor. Requested page size is
at most 99, leaving an original-owner lookahead budget of one within 100 rows.

`contributor::namespace_allowed(descriptor, namespace)` admits an exact trusted
authority root or a colon-delimited descendant. It rejects prefix lookalikes;
wildcard declarations are invalid. Namespace admission is not read authority.

## Focused Checks

`cargo test --manifest-path packages/search-core/Cargo.toml` covers conformance,
cache fencing, coordinator pagination/cancellation/isolation, and the exact
Messaging adapter via a test-only source inclusion. Projected reader probes
cover empty last-scanned pages and fresh no-store policy observations.
It does not build hosts or
claim native Social, Desktop/Mobile, performance, or formal Acceptance proof.
Host migration and dependent package lock updates belong to the integrator.
